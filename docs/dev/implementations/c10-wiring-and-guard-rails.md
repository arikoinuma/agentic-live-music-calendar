## Context

The Railway API answers anyone who finds its URL. `arch-initial.md` §5 chose a shared secret ("checked as a header on every request") and `env-setup.md` Phase 8 skipped it "since nothing enforces it yet"; C4's gate protects the Next.js *pages* only (C4-D6, "a courtesy, not security"). C10 closes that for the API, and does two smaller things the deployment plan lists beside it: bring the `main` ruleset's required checks up to date with the jobs added since C1, and check that the three Neon databases are in step. The Done-when is "a call to the Railway API without the secret is refused, and the calendar still renders."

It is a small milestone in code (one new module, one lifespan, one settings field, one header on the Next.js client, one new status row) and a careful one in rollout, because the failure it can cause is every calendar page answering an error. **Nothing about a hosted environment changes until its secret exists on both sides** (D13), and production's API does not run this code until C11 promotes the `production` branch (D1).

**K1 — the comparison is constant-time, on bytes, and a missing value takes the same road as a wrong one (`check_shared_secret`, D7, D8).**
- *Key point of interest:* the secret is compared with `secrets.compare_digest`, which takes the same time wherever two values first differ, so a caller cannot learn the secret one character at a time from response times. It is given **bytes**, because `compare_digest` on `str` raises `TypeError` for any non-ASCII text, and an attacker-chosen header can be non-ASCII (Starlette decodes headers as latin-1): a `str` compare would turn that into a 500, a visible difference from the 401 every other wrong value gets. A missing header (`None`) is a plain `False`, so "absent" and "wrong" are the same refusal (D7). **It differs from C4-D6's compare on purpose** (C10-PR1-8): that one hashes both sides first because a human-chosen gate password can be any length; here the value is machine-generated and `K2`'s floor keeps it long, `compare_digest` on raw bytes reveals only the secret's length, and a 64-character length is not worth hiding.
- *Code:*
  ```python
  if supplied is None:
      return False
  return secrets.compare_digest(supplied.encode("utf-8"), expected.encode("utf-8"))
  ```
- *Check:* `uv run pytest app/tests/test_security.py -k check_shared_secret`, then `app/tests/test_api_guard.py` (T1, T3). The likeliest mistakes: `supplied == expected` (passes every table row; wrong for timing), `compare_digest` on the `str`s (T4's non-ASCII row raises), or returning a truthy value for `None`.

**K2 — a hosted API refuses to start without a long enough secret (`shared_secret_problem`, D9).**
- *Key point of interest:* the rule is **fail closed**: on any hosted `APP_ENV` a missing or short secret is a start-up failure, because the alternative ("enforce when it is set") makes a forgotten variable a public API with a green deploy. The function is only called for a hosted environment: the lifespan skips `local` (a laptop's API is open by design), so that exemption is decided once, in the lifespan, and T6 tests it (C10-PR1-7). The 32-character floor turns a pasted placeholder into a refusal at deploy time rather than a guessable secret in production. The rule is in the API's own lifespan and not in `Settings`, so the worker, which builds `Settings` and never reads this variable, is unaffected. The returned sentence names the variable and never contains the value.
- *Code:*
  ```python
  if secret is None:
      return f"APP_ENV={app_env} but API_SHARED_SECRET is not set: a hosted API would answer anyone"
  if len(secret) < MIN_SECRET_LENGTH:
      return f"API_SHARED_SECRET is shorter than {MIN_SECRET_LENGTH} characters"
  return None
  ```
- *Check:* `uv run pytest app/tests/test_security.py -k shared_secret_problem`, then T6 in `test_api_guard.py`. The likeliest mistakes: treating `""` as set (the `Settings` validator already makes it `None`, but the function takes a plain `str | None`), an off-by-one at 31/32, or putting the secret's value into the sentence.
