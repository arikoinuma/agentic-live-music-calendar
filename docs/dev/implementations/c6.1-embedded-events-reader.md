## Context

The C6 held-out run failed on Hook & Ladder for a reason no model can fix. The page the worker fetches states each evening show's date **one day late** in its visible markup (`row-month`, `row-day`, `row-weekday`): 34 of its 41 events. A script in the live browser corrects them, which is why Ari's screenshot of the live site and the fetched text disagree. The model read the page faithfully and the page was wrong for it (C6 log round 9).

The same page carries the right answer twice, without any script running:

- each event's **slug**, `paul-cebar-tomorrow-sound-november-06-2026-730408`, names the local date in words;
- one `<astro-island>` element (component `EventsBrowser`, named in its `opts` and `component-url` attributes; the reader does not depend on the name) holds all 41 events as JSON in its `props` attribute: title, `date` and `time` (the listed time, `"2026-11-06T18:30:00.000-06:00"` and `"6:30 pm"`), `startTime`, `endTime`, `doorTime`, `priceRange`, `image`, `canceledAt`, `showSlug`, `performers`. The offset is the metro's (`-06:00` on all 41).

Checked on the captured page (`model_eval/captured_pages/hook_ladder-2026-11-04.html`, November 5, 2026): all 41 `date` values agree with their slugs; 34 differ from the visible row. That the visible dates are UTC-rendered is an inference (the page never says so).

This is the same situation the JSON-LD route already solves for schema.org pages (A2.1-D4): read the venue's own structured data with code, and ask a model only which acts a title names. So the work is a second **source of events** for that route, not a new pipeline. `jsonld.local_wall_clock` already converts a time with an offset or a `Z` into the metro's clock (A2.1-K1), which is the "generic UTC handling" Ari asked for: an embedded timestamp in UTC converts the same way.

**Out of scope here** (see "Not doing"): the Hook & Ladder model errors that are not dates (event names kept as acts, a comedy special kept as a show, two missed shows, a diacritic loss), the browser-based fetch, and the screenshot comparison (the last two are deferred in `arch-initial.md` §10).

## Test approach

Tests first (build plan §3); they stay red until the code exists. None needs a model.

- **The decoder and mapper**, on HTML written in the test in the shape Astro emits (`[0, value]` for a value, `[1, [...]]` for a list, the whole object HTML-escaped into `props`), with invented venues and artists. Expected dates and clock times are read from America/Chicago's 2026 rules (CDT until Sunday November 1, then CST), as `test_jsonld.py` does, not from the code under test.
- **The time rule (D3)**: an event with `startTime` uses it (even when `date` differs); with no `startTime`, an evening `date` with an offset is the start time; a `date` of `T00:00:00` with an offset and a `date` of `T00:00:00Z` each give a date and no time, on the *written* date (never the previous day); a `Z` evening converts to the metro's clock and, after the November 1 change, to the previous local day when UTC is early morning.
- **The shape cases**: a page with two islands (one irrelevant); an island that is not a list of events; an unknown Astro value type; invalid JSON; a missing `title` or `date`; a `Z` timestamp (generic UTC); a date-only value; a cancelled event; every `priceRange` shape in the real page (`"$22.65"`, `"$18.11 to $22.65"`, `"FREE"`, `None`).
- **The route**: a page with JSON-LD events and an island uses the JSON-LD (D2); a page with only an island routes as `jsonld`; a page with neither still goes to the model; `_route_for` and `extract_page` agree (they share `usable_events`).
- **The cross-check**: a slug date that differs from the converted local date yields one warning for that show; agreement yields none; a slug with no date yields none.
- **A test on the real page**, skipped where the capture is absent (as `test_validation_on_real_pages.py` does): the embedded reader on `hook_ladder-2026-11-04.html` returns 41 events; each labelled show's date (read from `labels.py`, which Ari wrote from the live site, not from this code) matches an event, and its time matches the event's `startTime` or, where the label still holds the printed door time (D3's consequence), is reported rather than failed; the listing text for Sleepy Weekend includes its support names (D8); **`_route_for` says `jsonld` and `validate_extraction` on the reader's output raises no `JSONLD_UNDER_REPORTED` and does not fall back** (`policy.route_falls_back` is false), so the fallback the reviewer found is pinned without a model (C6.1-PR1-1); the cross-check raises nothing.
- **The validation gate for the embedded source**: a page whose visible dates are shifted from its embedded events passes `validate_extraction`; a page whose embedded list is shorter than its visible dates by more than the slack still fails for a JSON-LD source (the check is unchanged there).
- **`_nothing_to_read`**: a script-shell page with only an island is not "nothing to read" (C6.1-PR1-6).
- **The measurement** (local, Step 6): the graph-level eval (`make eval-graph`) on the Hook & Ladder page with the 26B model, the same kind of run as the `c6-heldout` numbers it is compared with, and the gated set again to show the JSON-LD pages are unchanged.

Each dict carries `_source: "astro-island"` and `_slug`, and `jsonld.find_events` events are tagged `_source: "json-ld"` by `usable_events` (C6.1-PR1-6).
- Timestamps are not converted here. `to_structured_show` calls `local_wall_clock`, the single place a time with an offset or a `Z` becomes the metro's clock (A2.1-K1).

## Risks and traps

- **The island's shape is the site's own and can change.** The reader accepts only the shapes it understands and returns nothing otherwise; the page then falls back to the model route, which is today's behaviour. A silent fallback is acceptable here only because the cross-check and the eval would show the old date errors; say so in the module docstring.
