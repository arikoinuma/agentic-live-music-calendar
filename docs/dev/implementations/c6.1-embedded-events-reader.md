## Context

The C6 held-out run failed on Hook & Ladder for a reason no model can fix. The page the worker fetches states each evening show's date **one day late** in its visible markup (`row-month`, `row-day`, `row-weekday`): 34 of its 41 events. A script in the live browser corrects them, which is why Ari's screenshot of the live site and the fetched text disagree. The model read the page faithfully and the page was wrong for it (C6 log round 9).

The same page carries the right answer twice, without any script running:

- each event's **slug**, `paul-cebar-tomorrow-sound-november-06-2026-730408`, names the local date in words;
- one `<astro-island>` element (`component="EventsBrowser"`) holds all 41 events as JSON in its `props` attribute: title, `date` and `time` (the listed time, `"2026-11-06T18:30:00.000-06:00"` and `"6:30 pm"`), `startTime`, `endTime`, `doorTime`, `priceRange`, `image`, `canceledAt`, `showSlug`, `performers`. The offset is the metro's (`-06:00` on all 41).

Checked on the captured page (`model_eval/captured_pages/hook_ladder-2026-11-04.html`, November 5, 2026): all 41 `date` values agree with their slugs; 34 differ from the visible row. That the visible dates are UTC-rendered is an inference (the page never says so).

This is the same situation the JSON-LD route already solves for schema.org pages (A2.1-D4): read the venue's own structured data with code, and ask a model only which acts a title names. So the work is a second **source of events** for that route, not a new pipeline. `jsonld.local_wall_clock` already converts a time with an offset or a `Z` into the metro's clock (A2.1-K1), which is the "generic UTC handling" Ari asked for: an embedded timestamp in UTC converts the same way.

**Out of scope here** (see "Not doing"): the Hook & Ladder model errors that are not dates (event names kept as acts, a comedy special kept as a show, two missed shows, a diacritic loss), the browser-based fetch, and the screenshot comparison (the last two are deferred in `arch-initial.md` §10).

## Test approach

Tests first (build plan §3); they stay red until the code exists. None needs a model.

- **The decoder and mapper**, on HTML written in the test in the shape Astro emits (`[0, value]` for a value, `[1, [...]]` for a list, the whole object HTML-escaped into `props`), with invented venues and artists. Expected dates and clock times are read from America/Chicago's 2026 rules (CDT until Sunday November 1, then CST), as `test_jsonld.py` does, not from the code under test.
- **The shape cases**: a page with two islands (one irrelevant); an island that is not a list of events; an unknown Astro value type; invalid JSON; a missing `title` or `date`; a `Z` timestamp (generic UTC); a date-only value; a cancelled event; every `priceRange` shape in the real page (`"$22.65"`, `"$18.11 to $22.65"`, `"FREE"`, `None`).
- **The route**: a page with JSON-LD events and an island uses the JSON-LD (D2); a page with only an island routes as `jsonld`; a page with neither still goes to the model; `_route_for` and `extract_page` agree (they share `usable_events`).
- **The cross-check**: a slug date that differs from the converted local date yields one warning for that show; agreement yields none; a slug with no date yields none.
- **A test on the real page**, skipped where the capture is absent (as `test_validation_on_real_pages.py` does): the embedded reader on `hook_ladder-2026-11-04.html` returns 41 events, the dates the labels hold (read from `labels.py`, which Ari wrote from the live site, not from this code), and the cross-check raises nothing.
- **The measurement** (local, Step 6): the extraction-level eval on the Hook & Ladder page with the 26B model, and the gated set again to show the JSON-LD pages are unchanged.

## Decisions for the user / reviewer

| # | Decision | Recommendation |
|---|---|---|
| D1 | **The route keeps the name `"jsonld"`**, with a new note `structured_source` (`"json-ld"` or `"astro-island"`) saying which reader supplied the events. | Keep the name. A new literal touches `policy.Route`, `validation.Source`, the audit rows, the eval's gate lines and the committed baselines for no behaviour change, and "structured route" is what both mean. Cost: the name now says JSON-LD for something that is not. Rename later if a third source appears. **Ari's call.** |
| D2 | **Order**: JSON-LD events win; the embedded reader runs only when the page has no usable JSON-LD events. | A page with both has the same events twice; one source avoids duplicates and keeps every JSON-LD page's behaviour exactly as measured. |
| D3 | **Which time is the show's time**: the event's `date` (the listed time, which is what the page prints as `6:30 pm`), not `startTime`. | `date`. Ari's labels for this page hold the listed time (6:30 pm for a show whose `startTime` is 7:30 pm and whose `doorTime` is 6:30 pm). The listed time is also what a visitor sees. Whether the calendar should show doors or music is a product question for `requirements-initial.md`; this plan only matches the existing labels. **Ari's call.** |
| D4 | **End time**: map `endTime` to `endDate` and let the existing rules decide (within six hours of the start, and the page's visible text must state it, A2.1-D10). | Same rules as JSON-LD. The page does not print end times, so almost all will be dropped; that is the standard, not a loss. |
| D5 | **Price**: `"$22.65"` is the advance price; `"$18.11 to $22.65"` takes the lowest (the "from" price); `"FREE"` is `free_admission` true; `None` or text that does not parse leaves all three fields null. | Matches A2.1-D7 (a ticket price is the advance price) and "not stated is not false". The range rule is the one new choice; low stakes, **Ari may overrule**. |
| D6 | **The slug cross-check is a warning, not an error** (`CheckCode.SLUG_DATE_DISAGREES`), per show. It reports; it does not repair or drop. | The earlier agreement with Ari (C6 log round 9). It catches a feed whose embedded date and slug diverge, which would mean the feed itself is unreliable. On the one real page it never fires, so it is insurance; the plan says so rather than claiming it measured anything. |
| D7 | **Hook & Ladder stops being a held-out page for judging the model.** It was scored once (`c6-heldout`), its failure was diagnosed, and this milestone changes the pipeline because of it. A fresh held-out capture is needed before the gate is called. | Ari assembles the venue and adds a page labelled `held_out=True` (`docs/dev/adding-eval-venues.md`). Until then C6 Step 12 cannot honestly be run on the held-out set. **Ari's call.** |
| D8 | **The `performers` list is not used for acts.** | It strips punctuation (`"Paul Cebar Tomorrow Sound"` for `"Paul Cebar & Tomorrow Sound"`) and the splitter already has a measured contract. Revisit as its own question. |
| D9 | **No change to the model route or the prompts.** | This milestone is about where the dates come from. |

## Implementation steps

### Step 1 — tests first [written]

`agent_worker/tests/test_embedded_events.py` (decoder, mapper, shapes, price), additions to `test_extraction.py` for the route and to `test_validation.py` for the cross-check, and `tests/test_embedded_events_on_real_page.py` (skipped when the capture is absent). Each test opens with `Proves:`. Run them: they fail.

### Step 2 — the reader [written]

New `agent_worker/sources/embedded_events.py`. Module docstring in the style of `jsonld.py`.

- `find_events(html) -> list[dict]`: for each `astro-island` element, decode its `props` (BeautifulSoup already unescapes the attribute) from Astro's wrapping (`[0, v]` a value, `[1, [...]]` a list; any other type tag means the island is skipped, never raised) and look for a list of objects each having a string `title` and a string `date`. Return them as **schema.org-shaped dicts** (`name`, `startDate`, `endDate`, `image`, `offers`, `eventStatus`) plus `_slug`, so `jsonld.to_structured_show` runs unchanged. An unparseable island is skipped: one bad island must not cost the page its other events (the rule `jsonld.find_events` follows).
- The mapping from D3–D5: `date` -> `startDate`; `endTime` -> `endDate`; `priceRange` -> an `offers` price (D5); `canceledAt` not null -> `eventStatus` `EventCancelled`; `image`.
- Timestamps are not converted here. `to_structured_show` calls `local_wall_clock`, the single place a time with an offset or a `Z` becomes the metro's clock (A2.1-K1).

### Step 3 — wiring [written]

`usable_events(html)` returns the JSON-LD events, or, if there are none, the embedded ones (D2). `_from_jsonld` adds `notes["structured_source"]` and, for embedded events, `notes["slugs"]` (slug per show, in show order) beside `notes["titles"]`. `_route_for` needs no change (it calls `usable_events`).

### Step 4 — the cross-check [written]

`validation.check_slug_dates(extraction, notes)`: for each show with a slug, the date the slug names (`...-november-06-2026-<id>` -> 2026-11-06) against the show's date; a mismatch is a `WARNING`, `SLUG_DATE_DISAGREES`, `show_index` set. Wired into `validate_extraction` for `source == "jsonld"`. Add the code to whatever lists the codes for the audit rows (`audit.entry_for` reads findings generically; the build checks that).

### Step 5 — documents [written]

`docs/dev/notes.md`: the UTC-rendered visible dates and where the right ones are. `docs/dev/adding-eval-venues.md`: a note that a venue whose page embeds events is read by the structured route and what that means for its label. `apps/api/AGENTS.md`: one line on the second source. `docs/arch/arch-initial.md` §7: the route list.

### Step 6 — measure [written; local, needs the model]

1. Extraction-level eval on the Hook & Ladder page, 5 runs, 26B: wrong dates and times against the labels (before: 10 wrong time per run). Use the one-command environment override for the hosted endpoint; never edit `.env`.
2. The gated set, 5 runs: still passes, and every JSON-LD page's shows are byte-identical to `c6-prompt-v4`'s in date, time and price (only the splitter's answer can vary).
3. Record both in the Implementation log. Hook & Ladder's other errors are expected to remain (event names as acts and so on): report them, do not tune on them (D7, D9).

## Risks and traps

- **The island's shape is the site's own and can change.** The reader accepts only the shapes it understands and returns nothing otherwise; the page then falls back to the model route, which is today's behaviour. A silent fallback is acceptable here only because the cross-check and the eval would show the old date errors; say so in the module docstring.
- **`check_under_reported` compares the extraction with dates in the visible text**, and on this page the visible dates are the shifted ones. It may report the page as under-reported. Step 6 looks at the findings on this page; if it misfires, the plan's fix is to stop trusting the visible text on a page whose structured dates disagree with it, which is a design question for Ari, not a quiet change.
- **`end_time_is_stated` reads visible text**, and the end times live only in the embedded data (D4). Expect them dropped.
- **Two events with one title**: the route pairs shows with titles by position; a duplicate title is fine because order is kept.
- **Held-out discipline** (D7).
