## Context

`apps/api/agent_worker/eval/` held 17 modules in one flat folder. Ari, reading PR 78, could not tell from the folder which code runs on every scheduled fetch (none of it: nothing outside `eval/` and the tests imports it, checked by grep), which code measures a model on demand, and which only reads the results. The word "eval" also did not say what is evaluated, "pipeline" collides with the production pipeline, and "fixture" means three unrelated things in this repository (pytest fixtures, the frontend's generated `lib/fixtures/`, and the saved venue pages).

The purpose of the evaluation is to see whether the extraction process works with a given model; the model is the component being swapped, so the folder is named for it.

## Decisions

| # | Decision | Reason |
|---|---|---|
| D1 | `agent_worker/eval/` becomes `agent_worker/model_eval/`. It stays inside `agent_worker/`. | Says what it evaluates (Ari's purpose: choosing a model). Inside, because it only concerns the worker. |
| D2 | Two subfolders: `labelled_page_runs/` (runs the real extraction on hand-labelled pages: needs the model and Postgres) and `saved_run_reports/` (reads saved results: needs nothing). Shared and older files stay at the root of `model_eval/`. | Folder level now tells the three kinds apart. `labelled` matches the code's spelling (357 uses against 41). |
| D3 | `fixtures/` becomes `captured_pages/`, and `FIXTURES_DIR` becomes `CAPTURED_PAGES_DIR` (both in `capture.py` and `run_eval.py`). | "Fixture" is overloaded; `capture.py`, `captured_on` and the docs already say "capture". Not "snapshot": that names the committed result summaries. |
| D4 | The key `"fixture"` inside results files and the committed baselines stays, and so do the older tool's identifiers (`FixtureReference`, `gated_fixtures`, `load_text_fixture`, ...). | Renaming the key would change four committed baselines and break `--rescore` on raw files on Ari's laptop. The older tool was asked to stay as it is. A comment marks the key as stored data. |
| D5 | The tests move to `agent_worker/tests/model_eval/` and take their module's new name. | The same confusion applies to the tests: a dozen eval test files sat among the production tests. |
| D6 | A layering test enforces two rules: nothing outside `model_eval/` and the tests imports it, and `saved_run_reports/` never imports `labelled_page_runs/`. | Makes the folder boundaries permanent, in the style of `test_no_testing_imports.py`. |
| D7 | Implementation plans (`docs/dev/implementations/`) keep the names they were written with; living documents (`AGENTS.md`, the how-to docs, `arch`, `notes`, the Makefile, config) are updated. The mapping below is the key to the old names. | Plans are history. Rewriting them would falsify what each round saw. |

## Steps

1. Capture the reports of the four committed baselines (`--report --errors` for each, and `--compare` across them) before any change.
2. Move the files with `git mv` (history follows), create the two package folders and the tests folder.
3. Rewrite imports, module names in prose and comments, directory strings, and the Makefile, `pyproject.toml`, `.gitignore`, `.vscode/launch.json` and living documents, with a script, then fix by hand what a script cannot: the repository-root depth in `results_file.SNAPSHOT_DIR` (one folder deeper now), a name clash in the report tests (a helper called `results_file` against the new module of that name), the `__main__.py`.
4. Add `test_layering.py` (D6), tests first in spirit: it must fail when a deliberate violation is made.
5. `uv run ruff check`, `uv run mypy`, the full test suite, `make check`, `make designation-check`.
6. Re-run step 1's commands from the new location and diff: they must be byte-identical.

## For Ari, on the laptop, once

Git moves the tracked files but leaves the ignored folders where they are. After pulling:

```
cd apps/api/agent_worker
mv eval/fixtures model_eval/captured_pages
mv eval/results model_eval/results      # only if model_eval/results already exists, merge instead
rmdir eval 2>/dev/null || ls eval       # leftover __pycache__ is safe to delete
```

(`model_eval/` is created by the pull. If `model_eval/results/` exists already, move the files inside it rather than the folder.) Then run `make eval-report LABEL=c5-baseline` as a smoke check; it reads a committed snapshot and needs nothing else.
