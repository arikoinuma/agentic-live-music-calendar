## Context

`apps/api/agent_worker/eval/` held 17 modules in one flat folder. Ari, reading PR 78, could not tell from the folder which code runs on every scheduled fetch (none of it: nothing outside `eval/` and the tests imports it, checked by grep), which code measures a model on demand, and which only reads the results. The word "eval" also did not say what is evaluated, "pipeline" collides with the production pipeline, and "fixture" means three unrelated things in this repository (pytest fixtures, the frontend's generated `lib/fixtures/`, and the saved venue pages).

The purpose of the evaluation is to see whether the extraction process works with a given model; the model is the component being swapped, so the folder is named for it.

## Decisions

| # | Decision | Reason |
|---|---|---|
| D1 | `agent_worker/eval/` becomes `agent_worker/model_eval/`. It stays inside `agent_worker/`. | Says what it evaluates (Ari's purpose: choosing a model). Inside, because it only concerns the worker. |
| D2 | Two subfolders: `labeled_page_runs/` (runs the real extraction on hand-labelled pages: needs the model and Postgres) and `saved_run_reports/` (reads saved results: needs nothing). Shared and older files stay at the root of `model_eval/`. | Folder level now tells the three kinds apart. `labeled` is the American spelling (Ari, November 5, 2026, after first agreeing to `labelled` to match the code, which used it 357 times against 41; the rest of the code keeps `labelled` for now, see Round 3). |
| D3 | `fixtures/` becomes `captured_pages/`, and `FIXTURES_DIR` becomes `CAPTURED_PAGES_DIR` (both in `capture.py` and `run_eval.py`). | "Fixture" is overloaded; `capture.py`, `captured_on` and the docs already say "capture". Not "snapshot": that names the committed result summaries. |
| D4 | The key `"fixture"` inside results files and the committed baselines stays, and so do the older tool's identifiers (`FixtureReference`, `gated_fixtures`, `load_text_fixture`, ...). | Renaming the key would change four committed baselines and break `--rescore` on raw files on Ari's laptop. | D7 | Implementation plans (`docs/dev/implementations/`) and the other dated records keep the names they were written with: `alpha-build-plan.md` (history, per `AGENTS.md`), and in `alpha-deployment-plan.md` the checked-off items and the closed review rows. ## For Ari, on the laptop, once

Git moves the tracked files but leaves the ignored folders where they are, and the pull has already created `model_eval/captured_pages/` (it holds a tracked `.gitkeep`), so the pages go **into** it, not onto it. After pulling:

```
cd apps/api/agent_worker
mv eval/fixtures/* model_eval/captured_pages/       # your saved venue pages (the folder already exists)
mkdir -p model_eval/results
mv eval/results/* model_eval/results/               # raw run output, if you have any
ls -A eval                                          # only __pycache__ should be left; then: rm -rf eval
```

Then run `make eval-report LABEL=c5-baseline` as a smoke check; it reads a committed snapshot and needs nothing else. To check the pages landed, `ls model_eval/captured_pages | head` should list `.html` files directly (not a `fixtures/` folder).
